# 计分方式与落点

新比赛在赛前“高级设置”选择记分方式，规则模板也可以预设。目标分和计时设置独立于记分方式。

| 记分方式 | 主计分按钮 | 运动战落点 |
| --- | --- | --- |
| 标准计分 | 罚球 +1、+2、+3 | +2 线内，+3 线外 |
| 记球制，“三分球算 +2”关闭 | +1 | 整个可记录球场 |
| 记球制，“三分球算 +2”开启 | +1、+2 | +1 线内，+2 线外 |

记球制的“三分球算 +2”默认关闭。罚球通过明确的罚球操作记录；标准制主界面“罚球 +1”直接记罚中，罚失在“更多”的罚球操作组中。运动战未中可以在球场任意位置记录。

## 操作与提示

- 先记分后，在原有 10 秒窗口内补点：仅有效区域接收落点，无效区域变暗。误点不改变得分、不增加事件、不延长时限。
- 先选落点时，双方合法分值按钮实时启用；可以继续移动候选点。三分线边界按线内处理，底角直线和圆弧使用与绘制一致的几何。
- 在罚球线附近先选点，可以明确选择普通运动战得分或“罚球 +1”。罚球触达区域至少 48dp，且限制在线内。
- 罚球自动显示在罚球线中心，并短暂高亮确认。这个位置由罚球事件派生，不表示采集了实际出手坐标，不创建运动战落点或补点撤销步骤。
- 有效区域以约 1.6 秒周期缓慢明暗变化。减少或关闭动画时保持静态提示；暂停、进入后台、完成或离开时停止相应提示。
- 键盘方向键或读屏自定义操作可以移动候选点，再明确确认；球场矩形外的留白不产生边缘落点。

快速上手练习固定使用标准计分，落点步骤引导在线内选择位置后记录 +2。

## 数据与兼容

`RuleTemplate.scoringConvention` 是可空的计分约定，持久化值为 `standard`、`onePerBasket`、`oneAndTwo`。记球制界面只呈现一种方式及一个开关。模板使用已有元数据 JSON 保存该值，比赛规则快照保存当场选择；恢复、预设、再赛和连续对局都传递快照中的值。

缺少该字段的旧比赛和旧自定义模板继续使用原来的自由分值语义，不根据规则 ID 或按钮列表猜测含义。用户明确选择新的记分方式后，新比赛才采用区域约束。历史事件、导入记录和回放更正不回溯重判。

数据库保持 schema 4，备份保持 JSON 格式 2。空约定序列化时省略字段，保留旧开局命令的 payload 和指纹。罚球继续使用 `freeThrow` 事件；FG、FT 分母和运动战落点覆盖率分别计算。计分和补点仍通过现有命令事务、审计、回执及撤销路径处理。
