正式 release 包不可调试；`run-as` 会拒绝。正确参数顺序为 `run-as <package> --user <id> <command>`，包名在 `--user` 前。此限制和语法见 [AOSP run-as 源码](https://github.com/aosp-mirror/platform_system_core/blob/master/run-as/run-as.cpp)。真正的正式 v1/v2 验收使用下面的 root 文件路径；Debug 的 `run-as` 只适用于单独的调试验证，不能替代同证升级。

1. 可用签名配置由维护者在本机安全配置；按 [发行清单](release-checklist.md#4-android-正式签名) 用原证书构建 v2。记录固定应用源码提交、构建工具链、版本、SQLite 三种 ABI、权限、`allowBackup=false`、APK SHA-256，以及 `apksigner` 的完整验证输出。证书必须与上表逐字一致；任何失败都在安装前停止。
2. 在独立测试模拟器安装正式 v1，启动一次让应用建立私有目录，然后 force-stop。记录设备序列号、API、用户 ID、包 UID、正式 v1 APK 哈希和签名。保留空库原件，再注入夹具；不能从其他用户或设备复制真实比赛。

```powershell
$adb = 'D:/Android/Sdk/platform-tools/adb.exe'
$serial = '<dedicated-rootable-test-emulator>'
$userId = 0
$pkg = 'io.github.x1a0y4ngren.hooptrace'
$artifact = 'D:/DevCache/HoopTraceV2Artifacts/pre-release-20261005/upgrade'
$data = "/data/user/$userId/$pkg/app_flutter"
$v1 = 'D:/GitHub/hooptrace/build/release-assets/v1.0.0/HoopTrace-v1.0.0-android.apk'
$v2 = '<verified-original-certificate-v2-release.apk>'

& $adb -s $serial install --user $userId $v1
# 首次打开 v1，确认仅有空白测试资料，然后停止。
& $adb -s $serial shell am start --user $userId -n "$pkg/.MainActivity"
& $adb -s $serial shell am force-stop --user $userId $pkg
& $adb -s $serial root
& $adb -s $serial wait-for-device
# root 失败则停止。确认 serial/user/pkg/data 确实是该独立合成测试环境。
& $adb -s $serial pull $data "$artifact/v1-empty"
$packageLine = & $adb -s $serial shell cmd package list packages --user $userId -U $pkg
if ($packageLine -notmatch 'uid:(\d+)') { throw 'Cannot determine app UID' }
$appUid = $Matches[1]
& $adb -s $serial push "$artifact/schema2-fixture/hooptrace.sqlite" '/data/local/tmp/hooptrace-upgrade.sqlite'
& $adb -s $serial shell rm -f "$data/hooptrace.sqlite-wal" "$data/hooptrace.sqlite-shm"
& $adb -s $serial shell cp '/data/local/tmp/hooptrace-upgrade.sqlite' "$data/hooptrace.sqlite"
& $adb -s $serial shell chown "${appUid}:${appUid}" "$data/hooptrace.sqlite"
& $adb -s $serial shell chmod 600 "$data/hooptrace.sqlite"
& $adb -s $serial shell restorecon "$data/hooptrace.sqlite"
& $adb -s $serial shell am start --user $userId -n "$pkg/.MainActivity"
```

逐条检查原生命令退出码。首次启动、资料核对和界面出现是实际完成条件；命令序列中不使用固定 sleep 代替它们。注入前已保存空库，且删除仅限停止进程后的该独立测试库两个 WAL 辅助文件。

3. 在真实 v1 UI 检查上表历史、档案与活动比分，导出完整 JSON；force-stop 后将整个 `app_flutter` 拉到 `v1-before-upgrade/`，保留 DB、可能存在的 `-wal`/`-shm`，再运行下方 schema 2 检查。不要通过 PowerShell 重定向 `adb cat` 获取数据库二进制。
4. 覆盖安装正式 v2。保持同一个 Android 用户、UID 与私有数据目录；不卸载、不 clear、不使用 `-d` 或签名绕过。安装错误继续阻断。安装前强制停止，随后通过 `am start` 启动新的真实进程；记录旧 PID 消失、新 PID 出现，首次 UI、截图与日志。
5. 首次 v2 页面可用后先检查历史、名称/规则快照、三场 coverage 和活动 2:3，不进行业务修改。force-stop 拉取 `v2-after-migration/`，对全部原始表、receipt 与审计顺序执行 schema 3 检查。迁移可新增派生分析表；初始化可以增加偏好和内置规则，但不能改变夹具的原始行。

```powershell
& $adb -s $serial shell am force-stop --user $userId $pkg
& $adb -s $serial pull $data "$artifact/v1-before-upgrade"
& 'D:/Environment/Python313/python.exe' tool/release/prepare_v1_upgrade_fixture.py `
  --verify "$artifact/v1-before-upgrade/hooptrace.sqlite" `
  --baseline "$artifact/schema2-fixture/baseline.json" --expected-schema 2

# 仅在正式 v2 APK 已通过签名、来源和包配置核验后执行。
& $adb -s $serial install --user $userId -r $v2
if ($LASTEXITCODE -ne 0) { throw 'Formal same-certificate upgrade failed' }
& $adb -s $serial shell am start --user $userId -n "$pkg/.MainActivity"
& $adb -s $serial shell pidof $pkg
& $adb -s $serial shell dumpsys package $pkg | Select-String 'versionCode=|versionName=|userId='

# 上面的 v1 采集/检查在覆盖之前完成。正式 v2 冷启动与 UI 核对后：
& $adb -s $serial shell am force-stop --user $userId $pkg
& $adb -s $serial pull $data "$artifact/v2-after-migration"
& 'D:/Environment/Python313/python.exe' tool/release/prepare_v1_upgrade_fixture.py `
  --verify "$artifact/v2-after-migration/hooptrace.sqlite" `
  --baseline "$artifact/schema2-fixture/baseline.json" --expected-schema 3
```

6. 再次冷启动 v2，继续活动比赛并撤回一次，核对蓝方 +3 删除、红方 +2 及落点保留，比分 2:0。停止并冷启动后再次撤回，核对红方 +2 与原子确认落点撤回，比分 0:0。各次保存 DB、UI 和日志，确认新 undo 审计与 receipt 按顺序追加、旧审计/receipt 原文未改。原始 baseline 比较器只用于**业务修改之前**，不会把正常新增撤回当作迁移保留通过。
7. 在独立副本验证历史 `scoresOnly` 的 FG/FT 百分比不被误报为完整；`locations` 保持 1/2 落点覆盖且不含 FT。显式纠正 coverage 或结束确认才能改变声明，新审计/receipt 正常追加，原始事件保留。完成前后均核对导出完整 JSON 的可恢复性。

单独的 Debug 检查可先执行 `adb -s <serial> shell run-as io.github.x1a0y4ngren.hooptrace --user <id> pwd` 确认访问范围；`run-as ... cp app_flutter/hooptrace.sqlite /data/local/tmp/...` 通常也受目录权限限制，优先由 root 拉取，或使用 app 私有目录内的备份流程。无法访问正式私有目录且未在 v1 UI 录入等价合成场景时，保持 fixture 注入/逐行证据待验，不因换成 Debug 包而消除正式升级阻断。

如果未来实际执行此参考流程，需记录正式 v2 源提交、APK/证书哈希、设备、用户、PID、首次迁移前后库校验、两次冷进程撤回和 coverage 结果，再更新 [候选记录](v2.0.0-candidate.md) 与 [HANDOFF](../../HANDOFF.md)。本轮正式同证覆盖仅有历史准备，现按维护者选择豁免；既有 [文件升级回归](../../test/core/data/v2_file_upgrade_test.dart) 不能将它改标为通过。
