# HoopTrace 1.0 Implementation Plan

> Historical 1.0 plan, not a current assignment. Execution instructions and checkboxes below describe that task only; see [history scope](../README.md).

## Goal

Turn the v0.1 Android-first prototype into a reliable, offline-first 1v1 scoring, replay, and player-development app suitable for a single public 1.0 release through GitHub Releases and F-Droid.

## Global Constraints

- Remain permanently free, open source, offline-first, and without accounts, cloud sync, ads, payments, or telemetry.
- Deepen 1v1 for the next 2–3 releases. Do not add 3x3/5v5 or traditional full-team rebounds, steals, blocks, and turnovers.
- Release Android 1.0 only. Keep shared code and platform interfaces iOS-compilable; do not promise an iOS binary.
- Support complete Simplified Chinese and English localization.
- Use one shared court-first workspace for both recording modes. Compact phones score in landscape; large/foldable/multi-window layouts adapt without relying on orientation enforcement.
- Require the user to choose simple or detailed recording for every match.
- Simple mode: one-tap scoring, optional quick miss button, non-blocking location capture, quick undo. Detailed mode: court point first, then outcome and points; current possession preselects the shooter and remains manually correctable.
- Support count-up and countdown clocks. Running clocks continue according to UTC while backgrounded or killed. Countdown continuation becomes OT count-up.
- Allow exactly one active match. Process death must restore it from Drift, which is the single source of truth.
- Target/time end conditions pause input and request finish/continue confirmation; never auto-finalize.
- Player career aggregation uses stable player profile IDs. Temporary names are match-only until explicitly linked.
- Archive completed matches by default; permanent delete requires confirmation and cascades.
- Full backup restore supports replace and merge. Merge never auto-merges players by nickname and never steals the current active session.
- Day/night themes follow the system by default and can be manually locked.
- v0.1 database and backup compatibility is not guaranteed. Never silently wipe; detect schema v1 and show a blocking clean-install explanation.
- Preserve unrelated user files and existing untracked content. Do all work on `codex/hooptrace-1-0`.
- Commit each task separately. Do not push, publish, merge, submit F-Droid metadata externally, or change GitHub repository settings without explicit user authorization.

## Task 1: Pristine Test Foundation

**Objective:** Remove the existing Drift multiple-database warnings and provide reusable database test lifecycle helpers without changing production behavior.

**Work:**

- Add test utilities that create a unique in-memory executor/database per test and always close it.
- Migrate export/backup tests and any other affected suites to the helper.
- Keep warning suppression disabled; warnings must disappear because lifecycle ownership is correct.
- Add a regression test that opens and closes independent test databases without sharing executors.

**TDD:** Run the affected export tests and capture the warning as RED. Add the lifecycle helper, migrate tests, then run affected tests and the full suite as GREEN.

**Acceptance:** `flutter test --reporter expanded` passes 119+ tests with no Drift multiple-database warnings.

## Task 2: Dependency and Toolchain Modernization

**Objective:** Upgrade the main dependency families before new architecture is built on obsolete APIs.

**Work:**

- Upgrade Drift/drift_dev/drift_flutter, Flutter Riverpod, go_router, csv, file_picker, share_plus, path_provider, uuid, intl, and flutter_lints to the latest mutually compatible stable versions available during implementation.
- Upgrade in three commits or clearly separated migration steps: database; state/router; file/export/tooling.
- Regenerate Drift output and update call sites without changing user-visible behavior.
- Remove dependencies proven unused after a repository-wide reference check.
- Record resolved versions in the lockfile and update the third-party license generation/release notes if present.

**Acceptance:** formatting, analyze, all tests, Android debug build, and unsigned Android release build pass with the upgraded lockfile.

## Task 3: 1.0 Domain Model and Drift Schema v2

**Objective:** Establish the decision-complete 1.0 data contract.

**Work:**

- Add domain enums for recording mode, lifecycle, clock mode/phase, event kind, shot outcome, possession policy, restore mode, theme preference, and tracking coverage.
- Replace embedded red/blue name ownership with match participant rows containing side, name snapshot, and nullable player profile ID.
- Add clock state and singleton active-session tables; extend events for outcome, match-clock position, audit-safe soft deletion, and normalized custom labels.
- Make shot location one-to-one with a field-goal shot event. Extend possession segments with manual/suggested source.
- Add foreign keys, cascade behavior, indexes for active/history/replay/career queries, and schema exports.
- Set schemaVersion 2. A raw pre-open probe must identify schemaVersion 1 before Drift migration. Do not implement v1→v2 data migration or deletion.

**TDD:** Add domain invariant and in-memory schema tests before model/table changes; watch them fail for missing types/tables/constraints.

**Acceptance:** a fresh database passes integrity/foreign-key checks; schema v1 is detected as incompatible; schema migration tests establish the v2 baseline for future upgrades.

## Task 4: Transactional Match Command Kernel

**Objective:** Replace full-snapshot synchronization with atomic, idempotent commands backed by Drift.

**Work:**

- Implement `MatchCommandService` commands for start, record, correct, undo, pause, resume, finish, and abandon.
- Pre-generate command/entity UUIDs. Duplicate IDs return the committed result and never apply scoring twice.
- Enforce one active match through the active-session row and a transaction.
- Each correction or undo writes human-readable before/after audit data in the same transaction.
- Expose typed failures that retain the last committed projection and support explicit retry.
- Remove or retire snapshot rewrite paths from the existing session coordinator.

**TDD:** Cover atomic start, duplicate record, rollback on injected failure, correction audit, undo audit, finish clearing the active session, and simultaneous start rejection.

**Acceptance:** no UI-facing state can represent an uncommitted score; repository tests prove idempotency and rollback.

## Task 5: Persistent Match Clock and End Conditions

**Objective:** Implement reliable count-up/countdown timing and deterministic end-condition handling.

**Work:**

- Derive display time from persisted accumulated duration plus `runningSinceUtc`; do not write once per tick.
- Continue running while backgrounded/killed. Clamp and pause on backward wall-clock movement with a recovery message.
- Implement manual pause/resume events and persisted pause intervals.
- Countdown freezes at zero and enters regulation-expired. Continuing starts OT at 00:00 count-up.
- Target score plus win-by-two and countdown expiry pause input and return a finish/continue decision state; continuing target play re-evaluates only after the next score change.
- Foul limit emits a localized warning but does not end the match.

**TDD:** Use an injected clock to test exact boundaries, process-time reconstruction, clock rollback, OT transition, target acknowledgement, and win-by-two.

**Acceptance:** clock behavior is deterministic without timers in repository tests and restores correctly after reconstructing services.

## Task 6: Riverpod Composition and Active-Match Recovery

**Objective:** Make Drift-backed feature state the application composition root.

**Work:**

- Create providers for database, repositories, command service, clock, platform services, and feature controllers.
- Stop constructing repositories in the router; keep routing declarative and provider-aware.
- Replace in-memory-only controller lookup with `watchActiveMatch` and live projections.
- Add a home resume card showing participants, score, clock status, and last persisted time.
- Block new-match start until the user continues or explicitly abandons the active match.
- Provide keep-running, pause-and-leave, and stay actions when navigating away from live scoring.
- Add the v0.1 incompatible-database bootstrap screen.

**TDD:** Add provider/controller tests and widget tests for process reconstruction, resume navigation, new-match blocking, and legacy bootstrap.

**Acceptance:** rebuilding the entire widget tree with the same database restores the live match without retained controller objects.

## Task 7: Pregame Participants and Per-Match Mode Selection

**Objective:** Connect player identities and the selected recording mode to match creation.

**Work:**

- Let each side select a player profile or enter a temporary name.
- Prevent the same profile from occupying both sides; keep duplicate temporary display names allowed with explicit sides.
- Keep a participant name snapshot even when linked to a player.
- Present rules, count-up/countdown configuration, miss tracking, and simple/detailed mode in one start surface.
- Require an explicit mode selection every match and validate countdown duration/participants before start.
- Permit post-match linking of a temporary participant to a profile through an audited command.

**TDD:** Add controller and widget tests for profile selection, temporary names, duplicate-profile rejection, mode-required validation, and snapshot stability after profile rename.

**Acceptance:** started matches persist participant IDs/snapshots, mode, tracking coverage, rule snapshot, and clock setup atomically.

## Task 8: Shared Live Court Workspace and Recording Modes

**Objective:** Implement the approved court-first live interaction for both modes.

**Work:**

- Build a shared three-column live workspace with blue/red participant panels, central court, top clock, and bottom command dock.
- Simple mode provides one-tap score buttons, foul, undo, optional pinnable miss, and non-blocking “locate last shot”. Historical unlocated shots remain editable later.
- Detailed mode accepts court point first, then shooter/outcome/points; current possession preselects shooter and a visible control changes it before commit.
- Add free throw, foul, possession, pause, note, and custom-label actions without gesture-only controls.
- Trigger haptic feedback only after commit; optional sound is disabled by default and configurable.
- Maintain at least 48dp targets and avoid modal prompts during ordinary scoring.

**TDD:** Add controller tests before commands and widget tests for both flows, rapid input, failure/retry, location cancellation, shooter correction, and haptic-after-commit ordering.

**Acceptance:** both modes produce the same persisted event model; simple scoring remains one tap and detailed shots remain court-first.

## Task 9: Rules, Possession Segments, and Match Completion Flow

**Objective:** Make rules and possession behavior observable, configurable, and correctable.

**Work:**

- Extend rule templates with manual/switch-after-made/keep-after-made possession policy.
- Suggest possession after made shots according to policy; never infer missed-shot rebounds.
- Persist possession segments and close/open them atomically with manual or suggested changes.
- Allow immediate correction of suggestions and retain source/reason in audit data.
- Localize rule hints and end-condition prompts.
- Finish flow confirms final score, closes open possession/clock state, clears active session, and opens replay summary.

**TDD:** Cover all possession policies, missed-shot behavior, correction, segment boundaries, foul warning, finish/continue, and finalization rollback.

**Acceptance:** replay can reconstruct possession history and no rule condition silently finalizes a match.

## Task 10: Paginated History and Match Lifecycle

**Objective:** Replace the current join/N+1 history loading with scalable, searchable lifecycle management.

**Work:**

- Implement stable cursor or offset pagination with aggregate score/participant projection in one bounded query.
- Search by participant name/profile and filter by date, rule, recording mode, lifecycle, and archive state.
- Keep active matches out of ordinary finished history and expose them through recovery UI.
- Archive/unarchive completed matches. Permanent delete requires confirmation and cascades to events, locations, possessions, and audit data.
- Ensure career aggregates invalidate after participant linking and permanent deletion. Archiving is organizational and must not change career totals.

**TDD:** Add query-count/behavior tests with large fixtures, filter combinations, stable ordering, archive restore, and cascade deletion.

**Acceptance:** no per-row repository calls are made while loading a history page; 1000-match fixture first page meets the agreed performance target.

## Task 11: Replay, Correction Editor, and Human Audit

**Objective:** Make every recorded event reviewable and safely correctable.

**Work:**

- Present score summary, filterable full event timeline, court plot, analysis, and audit views.
- Plot made/missed shots and free throws with side/outcome/point filters.
- Edit side, event kind/outcome, points, match-clock position, location, and note; support soft delete and restoring a deleted event where valid.
- Validate edits against domain invariants and recalculate score/segments transactionally.
- Render localized, human-readable before/after changes, target labels, reasons, and timestamps.
- Split the existing oversized replay page into focused components/controllers.

**TDD:** Add editor validation, audit diff, score recalculation, filter, deleted-event, and replay restoration tests before UI changes.

**Acceptance:** every live event kind is visible in replay and all supported corrections leave an audit trail.

## Task 12: Single-Match and Career Analytics

**Objective:** Add truthful match analysis and player growth trends without overstating incomplete tracking.

**Work:**

- Compute scoring flow, lead changes, largest lead, scoring runs, shots/free throws, zone distribution, fouls, and possession segments.
- Add tracking coverage and exact location coverage. Do not show shooting percentage when miss tracking was not enabled for the full match; label all percentages as based on recorded attempts.
- Aggregate profile-linked matches into 7/30/90-day and all-time matches, wins, average points/margin, recorded shooting trend, zone heatmap, and recent change.
- Add opponent filtering/head-to-head while keeping growth as the primary hierarchy.
- Exclude temporary unlinked participants and abandoned matches from default career aggregates. Archived completed matches remain included.

**TDD:** Use hand-derived fixtures for incomplete tracking, partial locations, profile linking, archive/delete invalidation, opponent filter, and date windows.

**Acceptance:** career values match literal fixtures and incomplete data never produces a misleading efficiency claim.

## Task 13: Versioned Backup Replace, Merge, and Retention

**Objective:** Provide safe full-library disaster recovery and deterministic merge import.

**Work:**

- Define a 1.0 backup manifest with format version, app version, export time, entity counts, and checksum.
- Validate size, schema, enums, references, coordinates, active-session cardinality, and domain invariants before mutating local data.
- Replace mode creates a safety backup, stages validation, atomically replaces data, and restores a backed-up running match as paused.
- Merge keeps local settings; identical IDs/content skip, conflicting IDs/content remap the entire imported graph, and players never merge by nickname.
- Imported unfinished matches cannot replace the current active session and become resumable imported-incomplete records.
- Automatic Android SAF backup runs after match finish and after changed data has been unbacked-up for 24 hours; default retention 10, configurable within a safe bounded range.

**TDD:** Add full round-trip, rollback, every conflict type, corrupted input, v0.1/future rejection, active conflict, safety backup, and retention tests.

**Acceptance:** replace and merge are transactional and deterministic; failed imports leave byte-equivalent logical local data.

**TDD:** Add theme/settings tests, locale widget tests, accessibility guideline tests, golden tests for both themes/locales/sizes, and orientation/lifecycle tests.

**Acceptance:** critical flows pass at 200% text scale and TalkBack semantics checks; Android layouts work on compact landscape and large portrait/landscape surfaces; iOS no-sign build compiles in CI.
