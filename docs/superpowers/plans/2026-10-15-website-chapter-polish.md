# Hoopito · 球豆：章节视觉统一实施计划

> **For agentic workers:** Use superpowers:executing-plans or bounded parallel agents to implement task by task. 用户已要求“先写计划，然后实施”，本计划写完即执行；不增加确认环节。

**Goal:** 在保留已通过审阅的连续球场与交互基础上，改善体验区构图、复盘视觉衔接和手机下载阅读层级。

**Architecture:** 保留 Astro、GSAP 和单一背景 Three.js 场景。建筑剖切只影响装饰几何的可见程度；复盘氛围跟随既有卡牌时间轴，页面与演示状态继续各自负责内容和比分。手机使用现有二维球场。

**Tech Stack:** Astro / TypeScript / Three.js / GSAP / CSS / Playwright / Node 24。

**Spec:** 本对话已确认的三项下一步工作，以及 [网站说明](../../../website/README.md) 中的当前功能与验收约定。

## Global Constraints

- 继续电影级室内夜场：近黑、暖白、铜橙；保留品牌、Logo、字体、真实清洁截图和现有合格材质。
- 保留刚修好的 screen-up 运输、相机端点、24px 场地容纳边距、≤2 CSS px 投影误差、原生滚动及现有短暂停留。
- 保留三项计分点击演示、无默认选择、聚光箭头、540° 复盘卡牌、示例比分及其与真实截图不同的说明。
- 演示保持 6:6→8:6，1.20s 飞行、0.35s 穿网、0.58s 回弹、1.55s 落点；重置与多暂停原因行为不变。
- 手机不加载 Three.js/桌面材质；不增加模式切换或接管滚轮。减少动态效果保持相同排版。
- 仅本地实现、验证和审阅；不提交、推送、部署、更新/关闭 Issue、修改 HANDOFF 或执行 AOCI/项目收尾。保留已有未提交改动。

## Review Focus

1. 正反滚动和快速跨章时，建筑剖切与复盘压暗不能突然消失或残留。
2. 俯视时外围墙板、场外铜条和篮架后支撑不能形成遮挡；篮板、篮圈、篮网与真实投篮继续完整。
3. 200% 字号、360px 英文页面和展开说明时，完整版本号、按钮、FAQ 不得溢出或相互挤压。
4. 禁用控件不能出现可点击反馈；触屏、键盘焦点与减少动效均可辨认。
5. 无 JavaScript、WebGL 失败、首屏/体验占位和下载章节仍保持可读，不能因新增氛围状态隐藏正文。
