# AMD 合成层隔离实验计划

> 执行方式：在当前对话连续实施；使用系统排查、执行计划与验证技能。仅本地审阅，不提交、推送、部署、更新 Issue 或执行项目收尾。

**目标：** 用最多三组临时样式隔离，确认哪些具体效果与 AMD 跨章节提交长帧有稳定关系，再决定是否修改产品实现。

**依据：** 用户同意上一轮提出的三组隔离；既有报告为 `website/output/amd-fluidity-20261017/acceptance-report.md`。当前完整效果的三进程 18 个样本全部 p95 超标，实际呈现仍缺证。

**结构：** 保留当前网站分支及未提交改动。复用原 GPU 测量脚本与 native-wheel-v1 helper，生成忽略目录内的实验副本；临时 CSS 在完整开场校准和空闲后注入，每个浏览器关闭后消失。原测量脚本、产品源码和构建在筛选阶段不变。

## 1. 冻结与实验工具

- [ ] 校验上一轮最终源码／构建摘要，保存本轮冻结清单。
- [ ] 在 `website/output/amd-isolation-20261017/` 保存 profile 配置、原脚本／生成副本 SHA、精确注入规则、实际计算样式和原始测量。
- [ ] 工具测试先验证：插入点唯一、只支持允许的装饰属性、未知 profile 拒绝运行、控制组不改样式、原脚本不变、记录可区分诊断隔离与最终验收。
- [ ] CSS 审查确定三组互不重叠规则：仅隐藏 `.replay-card-sheen` 扫光；仅隐藏 `.replay-card-shadow` 投影；仅移除 `.scene-background` 的 mask-image（含 WebKit 别名）。玻璃、卡框阴影、章节铜光、背景覆盖层均保持，避免组内混杂。保留布局、540° transform、镜头和时间线。

## 2. 有界测量

- [ ] 只测 AMD 1920×1080／DPR2，原生滚轮进入体验、进入复盘、反向跨章。每次一个新浏览器进程，分别记录 cold／warmed；不同时运行其他测试、模拟器、录像或追踪解析。
- [ ] 第一轮顺序为 C0 → 扫光 → C1 → 投影 → C2 → 遮罩 → C3，共最多七个进程，每项都有相邻完整控制。保持实际 renderer、density/direct/1.5、缓冲区及输入序列一致；不一致样本保留并标为不可比较。
- [ ] 所有隔离结果仅诊断，不判完整产品通过。缺失呈现身份链继续 unavailable；不重试已无效的 timer query，不采集大型追踪。
- [ ] 只有某组至少一个场景 cold 与 warmed 的 p95 相对两侧控制均下降 ≥15% 且 ≥3ms，其他场景无 >10% 或 >2ms 回退，才作为筛选线索。筛选不是统计显著或根因证明。
- [ ] 最多选一组线索，追加两个交错控制／隔离配对，共最多四个进程；跨三次配对至少两次正收益，且不存在其他场景大于 2ms 回退。相邻控制漂移大于 max(3ms,15%) 时标为不确定，不声称因果。若没有稳定线索，停止本轮实验；若环境异常，可补一次替代样本，保留原样本。

## 3. 结果处理

- [ ] 有稳定线索时，先补产品失败回归，再实施一处保留完整视觉的等价优化；恢复完整效果执行三个独立进程复测，目标平均提交 ≥58 FPS、p95 ≤20ms。若仅删除效果才能获益，则不进入产品。
- [ ] 无稳定线索时保留全部数据、具体覆盖限制与证据缺口；产品源码及现有视觉保持原样。低密度历史配置和双 GPU 全矩阵继续暂缓。
- [ ] 仅为实际变更运行适用检查；未变的 103 单元、415 三浏览器及 38 WebGL、Android 路径证据继续按原来源引用，不冒称本轮重跑。
- [ ] 最终报告绑定本轮源码／构建、profile、样式有效性与所有失败样本；给出本地入口及下一步证据需求。

## 审查重点

注入前校准不能受到降成本样式影响；控制组与隔离组必须使用同一实验副本；计算样式必须确认规则生效；隔离不能改变几何或禁用动画；同进程首次与预热不能混为独立重复；删除效果的结果不能作为完整视觉性能验收。

## 本轮执行结果

冻结校验、工具及真实数据回归、三组加四个控制进程、独立数据审计已完成。43 项诊断工具／分析测试通过，42 个场景环境和样式资格成立，全部提交 p95 超标（20.3–35.2ms），控制漂移最高 10ms。三组均无稳定候选；额外配对、产品修正、完整视觉性能验收及全矩阵分支未触发。既有 41 个源码输入、62 个构建文件保持原样。详细结果与限制位于 `website/output/amd-isolation-20261017/report.md`。
