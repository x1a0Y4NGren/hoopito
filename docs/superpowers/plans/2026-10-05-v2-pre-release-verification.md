# HoopTrace v2 发布前任务计划

本计划由用户于 2026-10-05 批准执行。范围为启动性能、完整 CI、签名升级准备和设备验收；不进行 main 合并、公开 tag、GitHub Release、商店发布及发行资料收尾。

## 基线与约束

- 使用 `codex/hooptrace-v2` 候选工作区，基线 HEAD `a7a5491`、应用源码 `6d1b6cc068975d0aacfb92d10fb9828803f4e227`。
- 保留原 main 的全部未提交修改；版本 `2.0.0+4`、schema 3、JSON 格式 2 不变。
- 先完成可执行项，优先验证 host GPU 模拟器。正式签名配置缺失时记录阻断，继续独立任务。
- 证据注明实际源码、设备、渲染后端和构建模式。失败与降级样本保留，不放宽现有门槛。

## T1：启动性能与完整录屏

- [ ] 建立独立 API36 验证模拟器，通过运行日志确认实际 host GPU。现有 user10 保留，集成测试使用隔离用户。
- [ ] 添加仅 Profile 启用的准备耗时与降级原因，定位标准动作未播放和构建/绘制慢的来源。
- [ ] 按测量优化重复网格计算和无关重建，保留已审核 C Logo、48×48 网格、轨迹、表情保护、约一秒节奏及原有降级契约。
- [ ] 为测量工具添加可选 `--require-standard` / `--enforce-budget`，默认采集方式保持兼容。保存全部原始记录后才返回验收失败。
- [ ] 最终源码执行十次 Profile 冷启动：十次标准动作，可见阶段构建/绘制 p95 分别 ≤16.7ms。另录制标准动作至首页的完整连续视频，录屏与测量分开。

完成条件：全部门槛通过；GPU 不可用、降级或超预算均明确记录，不能替代通过。

## T2：完整远端 CI

- [ ] 本地最终检查后正常推送候选分支，并 `workflow_dispatch` 该 ref，记录实际 SHA。
- [ ] 通过质量、API24/36 集成、两份 fresh 源码的 Android 未签名可复现构建和 macOS iOS 无签名编译。
- [ ] 修复真实失败，不放宽依赖核验和查询/命令性能门槛；最终源码取得完整通过记录。

完成条件：最终候选提交全部 CI 作业通过；不创建 PR、合并 main 或发布。

## T3：正式签名准备与同证升级

- [ ] 核验现有正式公开证书与 v1 APK SHA-256，整理可重复升级步骤。
- [ ] 准备合成 v1.0 schema2 数据：历史、活动比赛、姓名/规则快照、事件、审计、撤回顺序。
- [ ] 配置可用后使用原证书构建 APK，核验 ID、版本、权限、SQLite 三种 ABI、签名和校验和。
- [ ] 安装正式 v1、写入 fixture、覆盖正式 v2，通过真实冷进程验证升级与继续撤回。

完成条件：正式同证升级通过。缺配置时仅完成准备，真实签名/升级继续阻断；不得创建替代证书或用 Debug 冒充。

## T4：最终候选设备验收

- [ ] API24/36 离线完整旅程：开赛、100/999、取消/重复开始、恢复活动比赛、记录/撤回、终场/再赛、档案/成长/分享。
- [ ] 真文件冷进程重启验证比赛、事件、时钟和撤回；核对纯记分/完整投篮/零出手/混合完整度统计。
- [ ] 系统分享、授权失效、后台 Worker 失败/重新授权、安全副本恢复；失败不破坏当前数据。
- [ ] 自然至少 24h 自动备份观察，记录真实调度/文件；强制 Worker 或改时间不替代自然验收。
- [ ] 双语、明暗、窄屏横屏、200% 字体、键盘、减少/关闭动画，恢复临时设置。

完成条件：可执行项通过；签名可用后补正式包验收。自然调度无实际结果前保持待验。

## 执行与交付

先准备设备与升级 fixture，再定位和优化 T1、固定源码，然后运行 T2/T4。签名条件满足才执行 T3 正式构建与升级。自然备份观察期间继续独立工作。

Dart 修改格式/分析/相关测试及受影响 Golden，最终源码全量测试；Python 测量回归，原生变更对应 Kotlin 测试。输入未变的有效证据可复用。

按任务提交代码和受影响文档，更新 HANDOFF/验收记录；产物保存仓库外，包含 Debug/Profile APK、SHA-256、录屏、十次原始测量、CI 链接及逐项结果。缺少正式签名、性能达标或自然调度证据时保留阻断，不标记发布就绪。
